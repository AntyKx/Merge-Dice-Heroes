# 合成操作異常調查

既有 `validate_battle_interactions.mjs` 已在 395×703 的實際 DOM 點擊下驗證：三名同職業同 T 英雄能一般合成，葫蘆的兩名免費合成亦能完成，兩次點擊調度不受影響。

目前以 `?fullBoardPreview` 進行視覺檢查時，畫面刻意以 16 名暫存英雄覆寫渲染資料，故不適合作為三名同英雄合成的互動重現。下一步會在不帶該旗標的隔離瀏覽器狀態下，以原生座標點擊三名騎士，確認新逐格定位是否阻擋觸控命中。

一般局內隔離狀態已建立三名 T1 騎士。依序實際點擊「合成」、第一名與第二名騎士後，介面顯示 `1/3`、`2/3`，說明工具列與前兩個絕對定位格的觸控命中均可用；下一步將完成第三格與確認鍵，並找出使用者實際無法合成時缺少的可讀性或防呆回饋。

第三名騎士點選後，合成提示正確顯示 `3/3` 並解鎖「合成升階」。點擊確認後，第一格保留一名 T2 騎士、其餘兩格清空，訊息顯示「三名合成完成！」。因此權威合成規則與新背景上的原生格子命中均正常；使用者看到無法合成更可能是目前沒有三名相同職業、相同 T 階英雄，需補強無合法組合時的即時說明。

三名 `fireMage` 隔離重現中，狀態物件雖有三筆資料，畫面只顯示兩名 T1 法師；`1-middle` 並非目前 4×4 棋盤所使用的有效 cell key。後續將讀取權威列名稱，依使用者截圖對應的真實三格重測，避免測試資料錯置造成誤判。

權威列名稱為 `front`、`midFront`、`midBack`、`back`。因此與使用者畫面相近的左上、第二欄頂列、左側第二列三名法師，應使用 `1-front`、`2-front`、`1-midFront`；先前的 `1-middle` 資料會被 UI 忽略，不可據以判斷合成互動。

以有效格位重建三名 T1 法師後，實際操作的合成計數依序從 `0/3`、`1/3`、`2/3` 到 `3/3`，第三名法師選取後，「合成升階」確認鍵如預期解鎖。此情境已排除法師職業或新格位選取的規則問題；接著將按確認完成升階，並針對使用者截圖中沒有選取計數／確認鍵的可見性改善操作提示。

根因已確認：短手機尺寸的舊版媒體規則將 `.bsv2-mode-hint` 設為 `display: none`，連帶隱藏「3/3」選取計數與「合成升階」按鈕，因此使用者即使選滿三名同階法師也無法確認。已在嵌入式戰場工具列套用更高優先權規則，永久顯示精簡確認列，並提前工具列位置避免覆蓋命運能量面板；實機開啟合成模式可見 `0/3` 與「需選 3 名」。

修正後的手機實機操作：依序點三名 T1 法師，確認列顯示 `1/3`、`2/3`、`3/3`，且「合成升階」按鈕全程可見；按下後留下 T2 燼焰法師並顯示「三名合成完成！」。因此使用者截圖的阻塞問題已被重現且修正。
